# End of Glory RTT

《荣耀终结》中文双人 RTT 模块。公开剧本为 `1914 Historical`，模块 ID 为 `end-of-glory`。

## 入口

- `rules.js`：RTT 服务端规则接口与确定性状态机
- `play.html` / `play.js` / `play.css`：游戏客户端
- `create.html`：创建页
- `about.html`、`rules.html`、`charts.html`、`cards.html`：介绍、规则、战斗表与卡牌图库
- `data.js`：浏览器和 Node 共用的编译数据

## 部署内容

本仓库只保存 RTT 服务器运行所需的规则、模块、客户端、`data.js` 和 `assets/` 运行时素材。测试、开发工具、地图编辑器、源数据、原始图包与规则书仅保留在本地，不提交到部署仓库。

## 人工初设

`rules.js` 中的 `set_up_historical_scenario()` 是 Historical 初设的唯一权威来源。初设采用与 POG 相同的剧本式写法：`setup_piece("ge", "德国骑兵", "Essen")`；第四个参数为 `true` 时表示减损面。手工修改第三个参数中的印刷地名即可，不需要坐标，也不需要重新生成 `data.js`。

仓库中不存在正式 `setup.json`。运行时不会读取 TTS 对象、坐标、GUID 或生成数据来建立 Historical 初设。

## 实现状态

RTT 公共接口、Historical 初设、地图/单位/牌组数据、基本行动循环、战斗与补给系统、海军、MO、补员升级、俄土战线、战争状态和终局框架已经可运行。118 张卡均有独立效果定义、卡面正文、合法事件路径和弃置/移除测试；27 张战斗牌使用独立 DRM、列移、火力表、地形、防御工事、撤退与挺进规则。移动采用 POG 式逐格状态机：每次仅开放相邻合法地区，逐格扣除移动力并改变控制权，服务器拒绝多格路径伪造；撤退会自动建立最大合法共同编队，仍允许玩家在第一步前拆队。

地图要塞具有完整 LF/CF、进入与维持围攻兵力、要塞战斗伤亡和围攻阶段掷骰；摧毁后自动获得 1 点防御工事。意大利 Historical 初设单位在 625 事件前保存在离图参战区，事件后按原位进场。六国 MO 使用 31 枚正式标记和跨回合实体布袋，执行半数洗回、余量不足时的分段抽取、具体进攻条件及未完成惩罚。补给分为全补给、友军有限补给、要塞有限补给和断补。

多步事件支持本方选择、对手响应、单位/地区目标、可选费用、取消、确认、回放和旧存档迁移。118 张卡均编译为结构化原子效果，运行时不解析卡面自然语言，也不存在通用 `rule` 回退。精确增援部署、动态 MO、延迟返场、跨回合 RP/卡牌返还、AEF 港口部署、保加利亚战线回退、美国 MO 即时反击、白羽毛强制 SR、施里芬预激活 SR、丘吉尔单位减损支付、皇家封锁港口限制、八月炮火重部署、处刑地维持与兴登堡防御工事均由服务器状态机执法。651“容克军官”可以作为事件使用，但事件本身没有规则效果。

战斗牌流程包含先制射击、结算前恢复、结算后响应与恢复、逐单位撤退距离、承受额外损失取消撤退、过堆叠损失后继续撤退、马恩河反击和尼维尔连续进攻。补牌前可由服务器流程弃置战斗牌，末行动轮损耗后可自愿清除孤立要塞单位、防御工事和战壕。补员阶段按卡面区分 A/US:RP 与 BR:RP：比利时只用 A/US，印度与英联邦可二选一，普通英国单位只用 BR。客户端只提交 `view.actions` 公开的动作，不自行修改状态，也不显示对手手牌或未揭示的海军选择。

星号牌只在作为Event（含Naval Event）或Combat揭示生效时移除；作为OP、SR、RP或普通Fleet使用时默认弃置，牌面明确的条件移除优先。版本34迁移只修复能够从当前状态或事件历史安全证明的卡牌区域；不能安全判断的历史弃牌不移动。运行时的卡牌守恒检查要求每张印刷卡恰好位于一个实际区域，重复或缺失会报告卡牌编号和冲突区域。版本36增加确定性状态推进：唯一移动/SR单位自动选中、普通进攻跳过无意义确认、固定数量事件自动继续、撤退自动建立最大合法编队、挺进第一格直接点击棋子完成；隐藏牌、可选效果、地图目的地和原子事件仍由玩家决定。版本37将内部进攻MO选择状态统一命名为`attack_mo`，旧存档会自动迁移。版本38加入三角单位规则：骑兵可使用RP修复但消灭后永久移除；印度步兵、BEF及德国东线部队不能使用RP修复或重建，印度骑兵仍按骑兵规则处理；有补给的LCU永久移除时仍正常放置预备区SCU。
